## 1. หน้าหลัก `/`
- **ส่วนหัว:** ชื่อแอป, คำอธิบายหนึ่งบรรทัด, ลิงก์ไป `/demo`
- **ตัวเลือกชนิด:** แท็บ "พยากรณ์รายวัน" | "พยากรณ์ 7 วัน"
- **ตัวเลือกวัน/รอบ:** ตั้งแต่ 11.6 ย้อนหลังได้ทุกฉบับที่เก็บ (ดูหัวข้อ 2h): รายวัน แต่ละวันมี 4 รอบ (05.00, 11.00, 17.00, 23.00) เรียงล่าสุดก่อน; 7 วัน: ฉบับที่ออกแต่ละวัน เรียงล่าสุดก่อน ค่าเริ่มต้นคือฉบับล่าสุด
- **มุมมองภาค:** การ์ด 7 ภาคพร้อมกัน + แท็บ/ตัวเลือกเพื่อโฟกัสภาคเดียว (โฟกัสแล้วเห็นการ์ดภาคเดียวใหญ่ขึ้น)
- **การ์ดภาค:** ชื่อภาค, ประโยคสรุปสภาพอากาศ (ฝน อุณหภูมิ ลม คลื่น หมอก), ฉบับ 7 วันแสดงเป็นรายการตามช่วงวัน, ส่วนข้อแนะนำ (ที่เกี่ยวกับภาคนั้น) พร้อมป้าย "ข้อแนะนำทั่วไป" สำหรับที่ใช้ทุกภาค
- **ส่วนท้าย:** ข้อความสงวนสิทธิ์ "ตัวช่วยสรุป ไม่ใช่ประกาศทางการ" และ "ที่มา: กรมอุตุนิยมวิทยา" ลิงก์ไปหน้าต้นฉบับของ TMD, วันเวลาของฉบับที่แสดง

## 2. หน้า `/demo`
- ช่องอัปโหลด PDF (ไฟล์จริง `<input type="file" accept="application/pdf">` พร้อมป้ายกำกับ, พื้นที่ลากวาง), ข้อความ "ไม่เก็บไฟล์ที่อัปโหลด", จำกัด 4 MB ตรวจในเบราว์เซอร์ก่อนส่ง
- ผลลัพธ์: ใช้การ์ดภาคชุดเดียวกับหน้าหลัก
- สถานะ: กำลังประมวลผล (busy), ผิดพลาด 4 แบบตามรหัสในสัญญาข้อมูล (`unsupported_document` ไฟล์ไม่ใช่ PDF ตั้งแต่ 10.3 (เดิม: ไม่ใช่พยากรณ์รายวัน/7 วันของ TMD), `too_large` ไฟล์ใหญ่เกิน, `extract_failed` อ่านข้อความไม่สำเร็จ, `empty_file` ไฟล์ว่าง) แต่ละแบบมีข้อความต่างกันและบอกว่าต้องทำอะไรต่อ
- แจ้งว่าผลจาก PDF อาจแม่นน้อยกว่าผลบนหน้าหลัก

**บันทึกออกแบบ Phase 5.2 (2026-11-17):**
- เบราว์เซอร์ส่ง PDF ดิบไป `POST /api/summarize` ตรง (ฟังก์ชัน Python) ไม่ใช้ Server Action เพราะ Server Action รันบน Node รันท่อ Python ไม่ได้ · ตอบกลับตรวจด้วย Zod ก่อนแสดง
- โครง (ทุกขนาดจอ เรียงจากบน): หัวข้อ `display-md` (มือถือ) / `display-lg` (≥ 640) → คำอธิบายบรรทัดเดียว → ข้อความสงวนสิทธิ์ → รายการสั้น 3 ข้อ (ไม่เก็บไฟล์, ไม่เกิน 4 MB, ผลจาก PDF อาจแม่นน้อยกว่าหน้าหลัก) → กล่องเลือกไฟล์ (การ์ดขอบเส้นประ `hairline-strong` มีข้อความกำกับ ไม่พึ่งเส้นขอบอย่างเดียว; `<input type="file">` จริงพร้อม label ตัวอักษร 16px; ลากวางได้) → ชื่อและขนาดไฟล์ที่เลือก → ปุ่มหลักสีดำ "สรุปพยากรณ์จากไฟล์นี้" (มือถือกว้างเต็ม) → พื้นที่สถานะ `aria-live` → ผลลัพธ์
- ฟอร์มกว้างสุด `max-w-2xl` ส่วนผลลัพธ์ใช้กริดการ์ดชุดเดียวกับหน้าหลัก (1 / 2 / 3 คอลัมน์ ใบสุดท้ายเต็มแถว) ผ่านคอมโพเนนต์ที่แยกออกมาใช้ร่วม
- สถานะ: ยังไม่เลือกไฟล์ (ปุ่มกดไม่ได้) · เลือกแล้ว · กำลังประมวลผล (ปุ่มกดไม่ได้ + ข้อความ "กำลังสรุป…" + Skeleton, กันส่งซ้ำ) · สำเร็จ (บอกชนิดและป้ายวันที่ของฉบับ + การ์ด 7 ภาค) · ผิดพลาด 4 แบบตามรหัส (`message_th` ของสัญญา; ขนาด/ชนิด/ไฟล์ว่างตรวจในเบราว์เซอร์ก่อนส่งด้วยข้อความเดียวกัน) · ติดต่อระบบไม่ได้ (เครือข่าย/คำตอบไม่ผ่านสัญญา) ข้อความแยก
- ข้อผิดพลาดใช้ `Alert` แบบ warning (แถบซ้ายสี + ไอคอน + ข้อความ ink) ไม่พึ่งสีอย่างเดียว

**/demo v2 (Phase 10.4, 2026-11-18, ดีไซน์ A):**
- ขอ `?trace=1` ทุกครั้ง (ผลสรุปเหมือนเดิมทุกไบต์) · รหัสข้อผิดพลาดตามความหมายใหม่: `unsupported_document` = ไม่ใช่ PDF, `extract_failed` = ภาพล้วน/อ่านหรือตรวจไม่ผ่าน
- 3 ระดับ: (1) รายวัน/7 วัน → ตัวเดินขั้นตอน + การ์ด 7 ภาคชุดเดิม (2) PDF อื่นที่มีข้อความ → ตัวเดินขั้นตอน + ผลโหมดทั่วไป (`app/demo/_components/generic-result.tsx`) (3) ภาพล้วน → ข้อผิดพลาด `extract_failed` · ชนิดที่สัญญามีแต่ยังไม่มีหน้าแสดงผล (เดินเรือ/เตือนภัย/สรุปรายสัปดาห์ แผน 11) → คำแจ้ง "ระบบอ่านเอกสารนี้ได้แล้ว แต่..." (ไม่ใช่ข้อผิดพลาด)
- ตัวเดินขั้นตอน (`trace-stepper.tsx`, Client Component): หัวข้อ h2 "ระบบทำอะไรกับไฟล์นี้ทีละขั้น", แถบความคืบหน้า (ตกแต่ง `aria-hidden`), "ขั้นที่ x จาก n" + ชื่อขั้น + คำอธิบายใน `aria-live`, ปุ่ม ย้อนกลับ/ถัดไป/ข้ามไปผลลัพธ์ (โฟกัสหัวข้อผล), ลูกศรซ้าย-ขวาเมื่อโฟกัสอยู่ในส่วนนี้ · ลำดับขั้นตาม `trace.steps` จากหลังบ้าน (ไม่ hard-code) · เปลี่ยนขั้น = ภาพของขั้นใหม่เล่นอนิเมชันใหม่
- ภาพต่อขั้น (`step-visual.tsx`): ตัวเลขสรุป (อ่าน PDF), บรรทัดก่อน/หลังทำความสะอาด, ป้ายชนิด, ภาคและจำนวนบรรทัด/หัวข้อ, รายการหน่วย, ชิปโทเคน (ไหลเข้าเหลื่อมเวลา), ชิปคัดคำ (ทิ้ง = เส้นประ + ขีดฆ่า + "ทิ้ง", ตัวเลข = พื้น `num-tint` + "→ <num>", นอกคลังคำ = เส้นประ + ข้อความ), แท่งคะแนน (ยืดจากซ้าย ร้อยละแสดงค่าสุดท้ายทันที) + คำที่ดันป้าย + จำนวนต่อป้าย, คำแนะนำต่อภาค, ค่าที่ดึงได้ 6 แถวแรก + "จาก: ต้นฉบับ", ประโยคตามแม่แบบ, รายการตรวจที่ติ๊กทีละข้อ, ตัวเลขผลลัพธ์ · คำอธิบายในภาพไม่พึ่งสีอย่างเดียว
- ผลโหมดทั่วไป: คำเตือนเมื่อไม่ใช่เอกสาร TMD, คำอธิบายว่าเป็นโหมดทั่วไป + จำนวนหน้า/หน่วย/ไม่แน่ใจ + คำอธิบายสัญลักษณ์ (พื้นฟ้า = ตัวเลข, ขีดเส้นใต้ = วันที่, ตัวหนา = จังหวัด), "ประโยคที่โมเดลจัดเป็นคำแนะนำ (คัดจากต้นฉบับ)", ปุ่มกรองตามภาค (`aria-pressed`) เมื่อมีหัวข้อภาค, ส่วนละการ์ด (หัวข้อ h3) แต่ละหน่วยมีป้าย + "มั่นใจ N%" + "ไม่แน่ใจ" (ป้ายเส้นประ), คำอธิบายศัพท์จาก TMD

## 2e. แท็บพยากรณ์เดินเรือบนหน้า `/` (Phase 11.1, 2026-11-18)
- แท็บชนิดที่สาม "พยากรณ์เดินเรือ" (`/?type=shipping`) และลิงก์ "เดินเรือ" ในหมวดพยากรณ์ของเมนู · จอแคบกว่า `sm` แท็บแสดงป้ายสั้น "รายวัน / 7 วัน / เดินเรือ" (ชื่อเต็มเป็น sr-only ไม่ตัดคำกลางบรรทัด)
- ไม่มีชิปเลือกภาค (แบ่งตามพื้นที่ทะเล; `region` ใน URL ถูกละ) · ป้ายฉบับ "พยากรณ์เดินเรือ ออกประกาศ ..." + ตัวเลือกรอบรายเดือน 2h (เวลาตามต้นฉบับ "13:00 น.")
- ลำดับ: การ์ด "ภาพรวมลมและคลื่น" (ประโยคคัดจากต้นฉบับ) → การ์ด "คำแนะนำสำหรับชาวเรือ" (คำต่อคำ แถบซ้ายสีเตือน) → การ์ด 4 พื้นที่ทะเลตามลำดับของ TMD (`components/features/shipping-summary.tsx`, h3 ชื่อพื้นที่, h4 ตอนบน/ตอนล่างของอ่าวไทย, บรรทัดใช้ `SummaryLines` เดียวกับการ์ดภาค) · 1 คอลัมน์บนมือถือ 2 คอลัมน์ตั้งแต่ `sm`
- ไม่มีข้อมูล (ยังไม่โหลดเข้า Neon หรือไม่มีโฟลเดอร์ใน `data/processed`) = กล่อง "ยังไม่มีข้อมูลพยากรณ์เดินเรือ" ไม่ใช่หน้าข้อผิดพลาด

## 2h. ตัวเลือกรอบแบบรายเดือน (Phase 11.6, 2026-11-18)
- ใช้กับหน้าแรกทั้ง 3 แท็บ (รายวัน เดินเรือ 7 วัน) และ `/summaries` (`components/features/month-picker.tsx` แทน `RoundPicker` เดิมที่ย้อนหลังแค่ 7 วัน) · `/warnings` มีรายการย้อนหลังจัดกลุ่มตามเดือนของตัวเองอยู่แล้ว (2f)
- กล่องเปิด-ปิด (`<details>`): หัว "เลือกรอบอื่น · ทั้งหมด N ฉบับ ใน M เดือน" · ภายใน: ลิงก์ "← เดือนก่อน (เดือน)" / "เดือนถัดไป (เดือน) →" ที่มีข้อมูล · ชิปทุกเดือนที่มี พร้อมจำนวนฉบับ ("พฤศจิกายน 2569 (5)") เดือนที่เปิดอยู่เป็นปุ่มดำ + `aria-current` · รายการของเดือนที่เลือก จัดกลุ่มตามวัน (รายวัน/เดินเรือ) หรือเป็นกลุ่มสัปดาห์ (สรุปรายสัปดาห์) ฉบับที่ดูอยู่เป็นปุ่มดำ
- URL: `?month=YYYY-MM` (เดือนตามเวลาไทย; รูปแบบผิด = ละ) + `?issue=<รหัส>` ลิงก์ตรงไปรอบได้ · ไม่ระบุเดือน = เดือนของฉบับที่เลือก ไม่มีฉบับที่เลือก = เดือนล่าสุด · เปลี่ยนแท็บชนิดล้างฉบับและเดือน · เปลี่ยนเดือนคงฉบับและภาค · เลือกเดือนแล้วหน้าโหลดใหม่และกล่องเปิดไว้ (`defaultOpen`)
- **ปฏิทินเลือกวัน (2026-11-19 แทนรายการวัน-รอบยาว):** หัวกล่องเหมือนเดิม · แถวเดือน = ปุ่มลูกศร ‹ › (ลิงก์ `aria-label` "เดือนก่อน (…)"/"เดือนถัดไป (…)" ไม่มีเดือนนั้น = ลูกศรจาง ไม่ใช่ลิงก์) + ชื่อเดือนและจำนวนฉบับ · ชิปทุกเดือนแถวเดียวเลื่อนแนวนอน (ซ่อน scrollbar) · ปฏิทิน 7 คอลัมน์ เริ่มวันอาทิตย์ (อา–ส) ช่องละ ≥ 44 px กว้างไม่เกิน `max-w-sm` · วันไม่มีฉบับ = จาง กดไม่ได้ ซ่อนจากโปรแกรมอ่านจอ · วันที่มีรอบเดียว (7 วัน เดินเรือบางวัน) = ลิงก์ตรงไปฉบับนั้น · วันที่มีหลายรอบ = ปุ่ม (`aria-pressed`) กดแล้วมีปุ่มเวลาเรียงเช้าไปค่ำใต้ปฏิทิน (เปิดวันของฉบับที่ดูอยู่ไว้ให้ ไม่มี = วันล่าสุดที่มีหลายรอบ) · วันถูกเลือก/ฉบับที่ดูอยู่ = พื้นดำ ตัวหนา (ไม่พึ่งสีอย่างเดียว) · ฉบับที่ป้ายวันเป็นเดือนก่อน (ออกหลังเที่ยงคืน เช่น 31 ต.ค. 23.00 น. ออก 00:00 น. 1 พ.ย.) แสดงเป็นปุ่มกลุ่ม "ออกหลังเที่ยงคืน" ใต้ปฏิทิน ไม่ถูกทิ้ง · ป้ายที่ไม่ใช่รายวัน (สรุปรายสัปดาห์) ใช้รายการชิปเดิม · ส่วนปฏิทินเป็น Client Component ใบเดียว (`day-calendar.tsx`) การเปลี่ยนเดือนและเข้าฉบับยังเป็นลิงก์ ไม่ต้องใช้ JavaScript
- **ตัวเลือกภาคบนมือถือ:** `RegionTabs` จอ ≥ 640 px (`sm`) เป็นชิปเหมือนเดิม · จอแคบเป็นลิ้นชัก (`Disclosure`) หัว "เลือกภาค · <ภาคที่เลือก>" เปิดแล้วเป็นตาราง 2 คอลัมน์ (ปุ่ม ≥ 44 px) ปิดเองหลังเลือก · สองชุดลิงก์ซ่อนด้วย `display: none` ชุดที่ไม่ตรงขนาดจอ จึงมี `nav` "เลือกภาค" ที่เห็นได้ชุดเดียวเสมอ
- ข้อมูล: `listIssueMonths(type)` นับต่อเดือน (SQL `to_char(issued_at at time zone 'Asia/Bangkok', 'YYYY-MM')`) และ `listIssuesInMonth(type, month)` (`lib/data/forecasts.ts`) · ซ่อนกล่องเมื่อมีฉบับเดียว
- ข้อจำกัดที่รู้: เดือนนับตามเวลาออกประกาศ (`issued_at`) แต่ป้ายรอบรายวันใช้เวลาของรอบ จึงรอบ 00.00 น. ที่ป้ายเป็น 23.00 น. ของวันก่อนหน้า (25 ฉบับ) ไปอยู่เดือนถัดไปเมื่อวันนั้นเป็นวันสิ้นเดือน ถูกต้องตามต้นฉบับ แต่อาจแปลกตา
- ข้อความ "ฉบับนี้อาจเก่ากว่า 7 วัน" ตัดออก (ย้อนหลังได้ทุกฉบับที่โหลด) · ข้อมูลตอนนี้: รายวัน 102 ฉบับ 7 วัน 21 เดินเรือ 100 สรุปรายสัปดาห์ 100 (12 เดือน)

ตรรกะอยู่ใน `lib/` (จัดรูปวันที่ไทย ป้ายภาค ค่าคงที่) ไม่อยู่ในคอมโพเนนต์ คอมโพเนนต์การตลาดของมาตรฐาน (mockup อุปกรณ์ ราคา ระบบนิเวศ รีวิว) ไม่สร้าง: ดู [design-system.md](design-system.md) หัวข้อ 5

## 4. เลย์เอาต์ตามขนาดจอ (จุดเปลี่ยนตาม docs/design/DESIGN-expo.md)
| จอ | การจัดวาง |
|---|---|
| มือถือ (< 640) | คอลัมน์เดียว ขอบข้าง 16px (`base`) เมนูบนเป็น hamburger (ต่ำกว่า 768) แท็บภาคเป็นแถบชิปเลื่อนแนวนอน ตัวเลือกวัน/รอบเป็นรายการเลือก ระยะห่างระหว่างส่วน 48px |
| แท็บเล็ต (640-1024) | การ์ดภาค 2 คอลัมน์ ขอบข้าง 24px (`lg`) |
| เดสก์ท็อป (1024-1280) | การ์ด 3 คอลัมน์ (ตาม "feature grid 3-up" ของมาตรฐาน) แท็บภาคอยู่ในแนวเดียวกับตัวเลือกอื่น ระยะห่างระหว่างส่วน 96px |
| กว้าง (> 1280) | กรอบเนื้อหาหยุดที่ 1200px จัดกลาง |
ตัดสินใน Phase 4.2 (2026-11-17): ใบสุดท้าย (กรุงเทพฯ) กว้างเต็มแถวทั้งที่ 2 และ 3 คอลัมน์ ส่วนข้อแนะนำทั่วไปเป็นการ์ดเต็มแถวเหนือการ์ดภาค (เดิม: เปิดเรื่อง ใบสุดท้ายเหลือ 1 ใบ)
ตัวเลือกภาคและชนิดพยากรณ์เป็นลิงก์ (`?region=`, `?type=`) ไม่ใช้ JavaScript ฝั่งเบราว์เซอร์ เมนูมือถือใช้ `<details>` · ทดสอบภาพหน้าจอที่ 375, 768, 1280 และ 320 สำหรับ reflow

## 5. ตัวอักษรและการเข้าถึง
รายละเอียดอยู่ใน [design-system.md](design-system.md): ฟอนต์ **Anuphan**, สเกลตัวอักษรของมาตรฐาน (line-height ปรับสำหรับไทย), เนื้อสรุปใช้ 16px ขึ้นไป, ไม่เว้นอักษร/ไม่จัดชิดสองข้าง/ไม่ตัวพิมพ์ใหญ่กับข้อความไทย, พื้นที่กดบนจอสัมผัส ≥ 44x44px, ความต่างสีข้อความ ≥ 4.5:1 ตามตารางที่คำนวณไว้ (ห้ามใช้ `muted`, `semantic-error`, `semantic-success` เป็นสีข้อความ), ระดับฝน/คำเตือนมีข้อความและไอคอน ไม่ใช้สีอย่างเดียว, รองรับคีย์บอร์ดและโฟกัสที่มองเห็น

## 6. สถานะที่ต้องมีในทุกมุมมองข้อมูล
กำลังโหลด (skeleton), ไม่มีข้อมูล (บอกสาเหตุ), ผิดพลาด (ปุ่มลองใหม่)

ทำแล้วใน Phase 4.3 (2026-11-17): กำลังโหลด = fallback ของ `<Suspense>` ในหน้า / (เปลือกหน้าแสดงทันที จึงไม่ใช้ `loading.tsx` ที่จะแทนทั้งหน้า) · ไม่มีข้อมูล = กล่องบอกสาเหตุ (ไม่มีฉบับเลย / ฉบับที่ขอไม่มีในระบบ พร้อมปุ่ม "ดูฉบับล่าสุด") · ผิดพลาด = `app/error.tsx` ปุ่ม "ลองใหม่" (ส่วนหัว/ส่วนท้ายอยู่ใน layout จึงยังเห็นเมนูและข้อความสงวนสิทธิ์) · ตัวเลือกรอบ/ฉบับย้อนหลัง = `<details>` จัดกลุ่มตามวันที่ในป้ายของ TMD ลิงก์ `?issue=`

## 2i. บรรทัดสรุปกระชับ (ADR 0020, 2026-11-23)
- การ์ดภาค/พื้นที่ทะเล: ป้ายไอคอน (ฝน/อุณหภูมิ/ลม/คลื่น) + ข้อความสั้นหนึ่งบรรทัดต่อชนิด เช่น "ฝนฟ้าคะนอง ร้อยละ 20 ของพื้นที่ · ลมกระโชกแรงบางแห่ง", "อากาศเย็น · ต่ำสุด 20-25 °C · สูงสุด 30-35 °C", "ลมตะวันออกเฉียงใต้ 10-15 กม./ชม." (เดินเรือเป็นนอต), "คลื่นสูงราว 1 ม. · ที่ฝนฟ้าคะนอง สูงกว่า 2 ม."
- รายชื่อจังหวัด (`SummaryLine.detail`): บรรทัดรองสี body ขนาดเล็ก ตัดที่ 2 บรรทัด ปุ่ม "ดูทั้งหมด/ย่อ" (`expandable-text.tsx`, client leaf, `aria-expanded`) โผล่เฉพาะเมื่อข้อความถูกตัดจริง · ข้อความครบอยู่ใน DOM เสมอ
- ความหมายระดับฝน/ความหนาว (`SummaryLine.notes`): `IssueSummary` รวมจากการ์ดที่แสดงอยู่ ไม่ซ้ำ ในกล่องพับ "ความหมายระดับฝนและอากาศ (ตามหมายเหตุของ TMD)" ใต้การ์ด (`lib/notes.ts`) ไม่มีระดับให้อธิบาย = ไม่มีกล่อง
- ไม่เปลี่ยน: ประกาศเตือนภัย สรุปรายสัปดาห์ ภาพรวม/คำแนะนำเดินเรือ และโหมดทั่วไป (คัดคำต่อคำ)

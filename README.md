# TMD Plain Forecast (สรุปพยากรณ์อากาศแบบอ่านง่าย)

เว็บที่เขียนพยากรณ์และประกาศของกรมอุตุนิยมวิทยา (TMD) ให้เป็นภาษาไทยที่อ่านง่าย แยกตามภาคและพื้นที่ทะเล ใช้วิธีที่เรียนในวิชา Natural Language Processing (NLP) และ Machine Learning (ML) เป็นงานกลุ่มรายวิชา ไม่ใช้เชิงพาณิชย์

- **Product (ใช้งานได้จริง):** https://tmd-plain-forecast.vercel.app
- **ตัวช่วยสรุป ไม่ใช่ประกาศทางการ** ข้อมูลทั้งหมดเป็นของกรมอุตุนิยมวิทยา (ดูเครดิตท้ายไฟล์) ถ้าต้องตัดสินใจเรื่องความปลอดภัย ให้ดูประกาศฉบับเต็มที่ https://www.tmd.go.th
- โจทย์ ขอบเขต สถาปัตยกรรม: [PLAN.md](PLAN.md) · ความคืบหน้าและประวัติการทำงานร่วมกับผู้ช่วย AI: [ai/](ai/README.md)

## 1. ไอเดีย (Idea, pain point, reference)

**ปัญหา (pain point)** ข้อความพยากรณ์ของ TMD เขียนครอบคลุมทั้งประเทศในแม่แบบเดียว ย่อหน้าภาพรวมยาว (ราว 1,900 อักษร) ตามด้วย 7 บล็อกภาค ผู้อ่านต้องหาเองว่าภาคตัวเองเป็นอย่างไร สาเหตุเชิงเทคนิค (ความกดอากาศสูง มรสุม) ปนกับคำเตือนในย่อหน้าเดียวกัน ตัวเลขอย่าง "ฝนฟ้าคะนองร้อยละ 30 ของพื้นที่" ไม่บอกความหมาย และฉบับ 7 วันต้องเรียงช่วงวันเอง รายละเอียดอยู่ใน [docs/spec/scope-and-pipeline.md](docs/spec/scope-and-pipeline.md) หัวข้อ 1 (ยังไม่ได้สำรวจผู้อ่านจริง ปัญหาข้างบนมาจากการอ่านเอกสารต้นฉบับ)

**ผู้ใช้** ประชาชนทั่วไปที่อยากรู้ว่า "ภาคที่ฉันอยู่ ช่วงนี้ต้องระวังอะไร"

**สิ่งที่ทำ** เว็บ 5 หน้า อ่านข้อมูลจากฐานข้อมูลและอัปเดตได้โดยไม่ต้อง deploy ใหม่

| หน้า | แสดงอะไร |
|---|---|
| `/` | พยากรณ์รายวัน (4 รอบ/วัน), 7 วัน และเดินเรือ (4 พื้นที่ทะเล) แยก 7 ภาค หรือโฟกัสภาคเดียว ย้อนหลังได้ทุกรอบที่เก็บ เลือกตามเดือน |
| `/warnings` | ประกาศเตือนภัยลักษณะอากาศ ฉบับล่าสุด ฉบับต่อเนื่องของเหตุการณ์เดียวกัน และย้อนหลัง |
| `/summaries` | สรุปสภาพอากาศรายสัปดาห์ แยกภาค พร้อมตารางฝนสูงสุด อุณหภูมิสูงสุด/ต่ำสุด |
| `/model` | อธิบายส่วน ML: ข้อมูล วิธีตัดสิน ผลวัด จุดที่ทายผิด (พยากรณ์ และแท็บประกาศเตือนภัย) |
| `/demo` | อัปโหลด PDF ของ TMD แล้วดูทีละขั้นว่าระบบทำอะไร พร้อมผลสรุป (ไม่เก็บไฟล์) เอกสารชนิดอื่นของ TMD ได้โหมดทั่วไป |

**ทำไมต้อง NLP / ML** ข้อความเป็นภาษาไทยไม่เว้นวรรค จึงต้องตัดคำ (PyThaiNLP `newmm` + พจนานุกรมคำอากาศ) แล้วจัดประเภทแต่ละประโยคว่าเป็นสภาพอากาศ (weather) สาเหตุ (cause) หรือคำแนะนำ (advice) เพื่อให้คำแนะนำไปอยู่ในการ์ดของภาคที่เกี่ยวข้อง ขั้นนี้ใช้ Naive Bayes และ k-NN ที่เขียนเอง (ตามข้อกำหนดรายวิชา ไม่ใช้ scikit-learn) เทียบกับกฎคำสำคัญ ส่วนขั้นอื่นเป็นกฎและ regex ที่เขียนเอง ระบบบอกตรงๆ ว่าขั้นไหนเป็น ML (หน้า `/model`)

**วิธี** ท่อประมวลผลบนเครื่องทีม แล้วส่ง JSON ขึ้นฐานข้อมูล

```
data/raw (ไฟล์ TMD เก็บมือ) -> ท่อ Python -> JSON -> npm run load:neon -> Neon Postgres -> Next.js บน Vercel
ตรวจชนิด -> เตรียมข้อความ -> ตัดคำ -> จัดประเภทประโยค (NB/k-NN) -> เลือกคำแนะนำให้ภาค -> ดึงค่า (regex) -> เขียนตามแม่แบบ -> ตรวจ F1-F7
/demo -> ฟังก์ชัน Python บน Vercel (api/summarize.py) ใช้ท่อเดียวกัน
```

**กติกาของผลลัพธ์ (ห้ามละเมิด)** ตัวเลข ชื่อจังหวัด และประโยคคำแนะนำทุกตัวต้องมาจากข้อความต้นฉบับของภาคนั้นคำต่อคำ ระบบไม่เขียนคำแนะนำเอง และไม่แปลง "ร้อยละ N ของพื้นที่" เป็น "โอกาสฝน N%" (ข้อความสรุปกระชับ ไม่มีค่าที่คำนวณเอง: รายชื่อจังหวัดอยู่ในบรรทัดรองที่พับได้ ความหมายระดับฝน/อากาศหนาวตามหมายเหตุ TMD รวมอยู่ในกล่องพับเดียวต่อหน้า ADR 0020) ประกาศเตือนภัย สรุปรายสัปดาห์ และภาพรวมพยากรณ์เดินเรือคัดคำต่อคำ ไม่เขียนใหม่

**ข้อจำกัด**
- **ป้ายที่ใช้ฝึกและวัดติดโดยโมเดลภาษา (Claude) ไม่ได้ผ่านคนตรวจ** ([ADR 0012](docs/decisions/0012-agent-labels-without-human-review.md)) ตัวเลข accuracy จึงวัดว่าโมเดลทำซ้ำป้ายชุดนี้ได้แค่ไหน ไม่ใช่เทียบกับป้ายที่คนยืนยัน
- ข้อมูลน้อย (หน่วยประโยค 292 หน่วยของพยากรณ์ และ 370 หน่วยของประกาศเตือนภัย) เก็บช่วง ต.ค.-พ.ย. 2569 (สรุปรายสัปดาห์ ธ.ค. 2568-พ.ย. 2569) ตัวเลขแกว่งได้ถ้าเปลี่ยนวันที่แบ่งชุด
- TMD ใช้ถ้อยคำเป็นแบบแผน กฎคำสำคัญจึงได้คะแนนสูงกว่าโมเดลที่เรียน ไม่ได้แปลว่ากฎจะดีกว่ากับถ้อยคำแบบอื่น
- ใช้ได้กับเอกสารของ TMD ที่รองรับเท่านั้น (รายวัน, 7 วัน, เดินเรือ, ประกาศเตือนภัย, สรุปรายสัปดาห์) เกษตร 7 วัน และคาดหมาย 3 เดือนเก็บข้อมูลไว้แล้วแต่ยังไม่ทำหน้าเว็บ (ไฟล์เหล่านี้เข้าโหมดทั่วไปของ `/demo`) PDF ของสรุปรายสัปดาห์เป็นแผนที่คนละเลย์เอาต์ จึงไปโหมดทั่วไปเช่นกัน
- PDF ที่เป็นภาพล้วน (ไม่มีชั้นข้อความ) อ่านไม่ได้ ระบบตอบข้อความบอกสาเหตุ (ไม่ทำ OCR) และกว่าจะตอบใช้เวลาราว 13 วินาทีเพราะลองตัวอ่านสำรองก่อน
- ยังไม่ได้ลองกับผู้ใช้จริง และยังไม่ได้ลองบนมือถือจริงนอกจากจำลองขนาดจอ

**อ้างอิง**
- ข้อมูล: กรมอุตุนิยมวิทยา https://www.tmd.go.th (รายละเอียดและเครดิต: [docs/data-sources.md](docs/data-sources.md))
- วิธีการ: เนื้อหาวิชา NLP (การตัดคำ, bag of words, Naive Bayes) และ ML (Naive Bayes, k-NN, การแบ่งชุดฝึก/dev/ทดสอบ) บันทึกอยู่ใน `course/notes/` · โจทย์: `course/slides/0_MiniProject.pdf` (ไม่ขึ้น repo)
- ไลบรารี: PyThaiNLP (ตัดคำ), pypdfium2 และ pdfminer.six (อ่าน PDF), Pydantic, Next.js, React, Tailwind CSS, Zod, Neon serverless driver, Playwright, Vitest · ฟอนต์ Anuphan (SIL OFL) · มาตรฐานดีไซน์ [DESIGN-expo.md](docs/design/DESIGN-expo.md) · รายการเต็ม: [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)

## 2. วิธีใช้ รัน และปรับแต่ง (How to use, run, customize)

### ใช้งาน
เปิด https://tmd-plain-forecast.vercel.app เลือกแท็บชนิดพยากรณ์ (รายวัน / 7 วัน / เดินเรือ) และภาค ดูย้อนหลังด้วยกล่อง "เลือกรอบอื่น" (เลือกเดือนแล้วเลือกรอบ) เมนู "เตือนภัย" "สรุปสภาพอากาศ" "ความรู้" พาไปหน้าอื่น ลองใช้ `/demo` ด้วย PDF พยากรณ์ของ TMD ไฟล์ละไม่เกิน 4 MB

### รันบนเครื่อง
ต้องมี Node.js (ทดสอบกับ 24) และ Python 3.12 ขึ้นไป (ทดสอบกับ 3.13) คำสั่งทั้งหมดรันที่รากของ repo

```bash
npm install
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[dev]"
npm run dev
```

เว็บที่ `http://localhost:3000` อ่านข้อมูลจาก `data/processed/` เมื่อไม่ตั้ง `DATABASE_URL` (มีผลสรุปครบทุกหมวดใน repo จึงรันได้เลย) หมายเหตุ: `/demo` บนเครื่องที่รันด้วย `npm run dev` ตอบว่าติดต่อระบบสรุปไม่สำเร็จ เพราะฟังก์ชัน Python (`/api/*`) มีเฉพาะบน Vercel ส่วนที่รันฟังก์ชันได้ด้วย pytest ผ่านเซิร์ฟเวอร์จำลองใน `tests/api/`

> โฟลเดอร์ของโปรเจกต์นี้อยู่ในพาธที่มีเว้นวรรคและเครื่องหมาย & `npm run <สคริปต์>` เรียก `node node_modules/...` ตรงๆ เพราะ shim ใน `node_modules/.bin` พังกับพาธแบบนี้ (ถ้าพาธของคุณไม่มี & ก็ใช้ได้ปกติ) บน Windows ใช้ `.venv/Scripts/python.exe` ส่วน macOS/Linux ใช้ `.venv/bin/python`

### ตัวแปรสภาพแวดล้อม
คัดลอก `.env.example` เป็น `.env` (อยู่ใน `.gitignore` ห้ามใส่ค่าจริงใน repo หรือแชต) ตัวแปรที่ใช้: `DATABASE_URL` (Neon role อ่านอย่างเดียว ใช้บน Vercel), `DATABASE_URL_DIRECT` (role เจ้าของ ใช้เฉพาะสคริปต์โหลดบนเครื่อง), `REVALIDATE_SECRET` และ `SITE_URL` (ล้างแคชหลังโหลด) ไม่ต้องมี `.env` ถ้าแค่รันเว็บจากไฟล์ใน `data/processed/`

### ตรวจและทดสอบ
```bash
.venv/Scripts/python.exe -m pytest -q          # เทสต์ Python
.venv/Scripts/python.exe -m ruff check .       # lint Python
npm run build                                   # build (สร้างไทป์ของเส้นทางที่ typecheck ต้องใช้)
npm run typecheck
npm run lint
npm test                                        # Vitest
npm run e2e                                     # build แล้วรัน Playwright บน Microsoft Edge ที่ติดตั้งในเครื่อง
npm run smoke                                   # ทดสอบเว็บจริง (SMOKE_URL เปลี่ยนเป้าได้)
```
ตัวตรวจข้อมูลและความถูกต้องของผล (ต้องพิมพ์ `errors: 0`): `scripts/check_fidelity.py`, `check_shipping.py`, `check_warnings.py`, `check_weekly.py`, `check_generic.py`, `check_raw.py` (รันด้วย `.venv/Scripts/python.exe -X utf8 scripts/<ชื่อ>.py`)

### รันท่อประมวลผลและโหลดข้อมูล (ทีมเท่านั้น)
`data/raw/` (ข้อมูลดิบของ TMD เก็บมือ 1,481 ไฟล์) ไม่ขึ้น repo จึงต้องมีสำเนาจากทีมก่อน
```bash
.venv/Scripts/python.exe -X utf8 scripts/run_pipeline.py   # data/raw -> data/processed/*.json (ซ้ำได้ผลเดิมทุกไบต์)
.venv/Scripts/python.exe -X utf8 scripts/check_fidelity.py
npm run load:neon -- --dry-run                              # ตรวจทุกไฟล์ด้วยสัญญาข้อมูลชุดเดียวกับเว็บ ไม่ต่อฐานข้อมูล
npm run load:neon                                           # โหลดเข้า Neon แล้วสั่งเว็บล้างแคช (ต้องมี .env)
```

### ปรับแต่ง
- **เพิ่มชนิดเอกสาร:** เขียนแพ็กเกจใน `src/tmd_plain/doctypes/<ชนิด>/` (แยกโครง, สร้างผล, ตัวตรวจ F) แล้วเพิ่มรายการเดียวใน `doctypes/registry.py` ไม่ต้องแก้ `service.py` สัญญาข้อมูลอยู่ใน `src/tmd_plain/contract.py` (แก้แล้วรัน `scripts/export_schema.py`) รายละเอียด: [docs/spec/data-contract.md](docs/spec/data-contract.md)
- **ฝึกโมเดลใหม่:** ปรับค่า m/k และแบ่งชุดใน `src/tmd_plain/config.toml` แล้วรัน `scripts/train_eval.py` (พยากรณ์) หรือ `scripts/train_eval_warning.py` (ประกาศเตือนภัย) ได้ `models/*.json` และ `docs/results/*-evaluation.md` ซ้ำได้ผลเดิมทุกไบต์ ปรับ m/k บนชุด dev เท่านั้น ห้ามดูชุดทดสอบ
- **ถ้อยคำคำอธิบายระดับฝน/ความหนาว:** `src/tmd_plain/resources/glossary.toml` (ตามหมายเหตุของ TMD เท่านั้น)
- **หน้าตาเว็บ:** โทเคนดีไซน์อยู่ใน `app/globals.css` ตามมาตรฐาน [DESIGN-expo.md](docs/design/DESIGN-expo.md) (อ่านอย่างเดียว) ข้อปรับสำหรับภาษาไทยอยู่ใน [docs/spec/design-system.md](docs/spec/design-system.md)

## 3. ข้อมูลและผลลัพธ์ (Data and results)

ท่อประมวลผลรันทุกฉบับที่เก็บ ไม่มีฉบับที่ไม่ผ่านตัวตรวจ ([pipeline-run.md](docs/results/pipeline-run.md)) ฐานข้อมูลจริงหลังโหลด 478 แถว ขนาดทั้งฐาน 10.27 MB ([smoke-test.md](docs/results/smoke-test.md)) เกษตร 7 วัน (667 PDF) คาดหมาย 3 เดือน (31 PDF) และชุดทดสอบโหมดทั่วไป (7 PDF) เก็บไว้แต่ยังไม่มีหน้าเว็บ

### โมเดลจัดประเภทประโยค: การแบ่งชุดและผลวัด
แบ่งตามวันที่ประกาศ (ไม่สุ่มปนกัน ไม่ให้โมเดลเห็นวันทดสอบ) ปรับ m ของ Naive Bayes และ k ของ k-NN บนชุด dev เท่านั้น กฎคำสำคัญ (baseline) เขียนก่อนมีป้าย ไม่ได้ฝึกหรือปรับ

**พยากรณ์รายวัน/7 วัน** (292 หน่วย, 4 ป้าย: weather, advice, cause, other; ฝึก 118 · dev 28 · ทดสอบเป็นวันล่าสุด 7 วัน) ที่มา: [classifier-evaluation.md](docs/results/classifier-evaluation.md)

| ตัวจัดประเภท | dev | ทดสอบ ทุกหน่วย | ทดสอบ ถ้อยคำใหม่ (120 หน่วย) |
|---|---|---|---|
| Naive Bayes (ตัวที่เลือกจาก dev) | 96.4% | 96.1% | 96.7% |
| k-NN | 85.7% | 91.4% | 91.7% |
| กฎคำสำคัญ (baseline) | 100.0% | 99.2% | 99.2% |

**ประกาศเตือนภัย** (370 หน่วยไม่ซ้ำ จาก 155 ฉบับ, 3 ป้าย: weather, cause, advice; แบ่งตามเหตุการณ์: ฝึก 239 · dev 56 · ทดสอบ 75 หน่วย) ที่มา: [warning-classifier-evaluation.md](docs/results/warning-classifier-evaluation.md)

| ตัวจัดประเภท | dev | ทดสอบ | macro-F1 ทดสอบ |
|---|---|---|---|
| Naive Bayes (ประกาศ) | 100.0% | 98.7% | 98.8% |
| k-NN (ประกาศ) | 100.0% | 98.7% | 98.8% |

| Naive Bayes ของรายวัน (ไม่ฝึกใหม่) | 98.2% | 92.0% | 93.1% |

**อ่านผลอย่างไร:** กฎคำสำคัญได้คะแนนสูงกว่าโมเดลที่เรียน เพราะป้ายของผู้ช่วยตรงกับกฎ 288 จาก 292 หน่วยตั้งแต่ก่อนวัดผล และ TMD ใช้ถ้อยคำเป็นแบบแผน ไม่ได้แปลว่ากฎดีกว่าโดยทั่วไป โมเดลที่เรียนยังเป็นข้อกำหนดรายวิชา ใช้งานจริงในท่อประมวลผล และใช้ตรวจหน่วยที่กฎกับโมเดลเห็นต่างกันได้ dev มีแค่ 28 หน่วย (ประกาศ: advice 7 หน่วย) ทุกค่า m ได้คะแนนเท่ากัน จึงเลือกค่าแรก ตัวเลขเหล่านี้แกว่งได้มาก

**วิเคราะห์ข้อผิดพลาด (error analysis)** Naive Bayes ของพยากรณ์ทายผิด 4 หน่วยจากชุดทดสอบ 120 หน่วย ทั้งสี่มีเหตุที่อธิบายได้ ดูตารางพร้อมข้อความใน [classifier-evaluation.md](docs/results/classifier-evaluation.md) และหน้า `/model`: (1) คำแนะนำที่มีวลีเหตุผล "เนื่องจากสภาพอากาศที่หนาวเย็นลง" ถูกดึงไป cause เพราะชุดฝึกมี advice แค่ 21 หน่วย (2) ประโยคคลื่นลมใช้คำเดียวกับประโยคมรสุม ("มีกำลังแรงขึ้น" อ่าวไทย ทะเลอันดามัน) และ bag of words ไม่รู้ลำดับคำ (3) หน่วยที่ปนกลไกกับคลื่นกับอากาศช่วงถัดไป ซึ่งป้ายเองก็ก้ำกึ่ง (4) วลี "เริ่มมีกำลังอ่อนลงเป็นกำลังปานกลาง" พบบ่อยในประโยคมรสุมของชุดฝึก ป้าย `other` มีหน่วยเดียวในข้อมูลทั้งหมด โมเดลจึงแทบทายป้ายนี้ไม่ได้ ส่วนโมเดลของประกาศเตือนภัยทายผิด 1 จาก 75 หน่วย (ดู `/model/warning`)
